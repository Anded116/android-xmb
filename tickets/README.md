# Тикеты XMB-лаунчера

Файловый jira-like трекер: **один markdown-файл = один тикет**, всё в репозитории, без облаков. Обзор —
`tickets/board.html` (UI в браузере) и [BOARD.md](BOARD.md) (то же текстом; оба генерируются, руками не править).

Перенесён из «Колонизации» (`G:\work\colonisation-game`), а туда — из Ainimator Studio, где проверен в бою; другие
только префикс номеров (`LNC`), области и способы проверки.

## Для кого и зачем

Код здесь пишут агенты, поэтому без тикетов решения автора живут только в стираемом контексте сессии.

- **Человек, который решает.** Решение, принятое в чате («док в магазинной сборке выключен»), не должно потеряться
  с концом сессии и через месяц обсуждаться заново. → `decision`-тикет в ту же сессию: что решили, почему, что
  отвергли, что теперь обязаны соблюдать.
- **Человек, который проверяет.** Одним списком — что агент считает сделанным и как это проверить на телефоне
  или приставке; отметить «работает / не работает», не пересказывая вердикты в чат. → `fixed` ≠ `verified`,
  `verify-in`, вкладка «Ревью» в board.html, `apply`.
- **Агент в новой сессии.** За минуту понять, что открыто, что в работе, что решено и почему. → доска, «История»
  каждого тикета, `links`, `commits`.
- **Агент посреди задачи.** Найденный баг вне задачи или отложенная работа записываются, а не остаются TODO
  в чате. → `new -Type bug|tech`.
- **Несколько сессий и машин.** Тикеты заводятся без сервера и согласования номеров. → файлы в git, буква автора
  в номере (`LNC-A0001`), `renumber`, трекер на node.
- **Тот, кто читает код потом.** Странное правило в коде (почему нет службы спец. возможностей в store) находится
  по номеру тикета в коммите и комментарии.

## UI — `tickets/board.html`

Открывается двойным кликом, без сервера и интернета. Генерируется командой `board` и в git не хранится.

- **Доска** — поиск и фильтры; клик по строке разворачивает тикет.
- **Ревью** — все `fixed` по способу проверки, кнопки «✓ работает» / «✗ не так» (отметки в localStorage).
- **Новый фидбек** — форма для того, на что тикетов ещё нет.
- **Выгрузка для агента** — готовые команды `node tools/tickets.mjs set ...`.

Страница ничего не пишет в репозиторий; единственный путь изменения тикетов — CLI.

## Команды

```bash
node tools/tickets.mjs <команда> [аргументы]
```

Без пакетов, одинаково на любой ОС; `tools/tickets.ps1` (Windows, UTF-8 с BOM) и `tools/tickets.sh` только
вызывают его. Опции — `-Title` (регистр не важен) или `--title`.

| Команда | Что делает |
|---|---|
| `new -Type bug -Title "..." -Priority P1 -Area ui [-Source user] [-VerifyIn review] [-Labels watch] [-Links LNC-A0001] [-Note "..."]` | заводит тикет: номер — буква автора по git e-mail из `tickets/authors.json` и следующий общий номер; slug из заголовка |
| `set -Id LNC-A0042 -Status fixed [-Type feature] [-Commits abc1234] [-Note "..."] [-Force]` | меняет frontmatter, обновляет `updated`, пишет строку в «Историю» |
| `list [-Status open] [-Type bug] [-Area ui] [-Priority P0]` | таблица; без фильтров — только активные |
| `checklist` | «что проверить»: все `fixed` по способу проверки |
| `board` | перегенерировать BOARD.md и board.html |
| `validate` | проверить все тикеты (выход 1 при ошибках) |
| `renumber [-Path ...]` | номер занят дважды после слияния веток |
| `apply [-Path tickets/feedback.json]` | применить фидбек из board.html |

Frontmatter правится **только через `set`**; тело тикета — обычным редактированием файла.

## Поля

`id` `title` `type` `status` `priority` `area` `source` `verify-in` `created` `updated` `links` `commits` `labels`

- **type**: `bug` | `feature` | `tech` | `decision` | `question`
- **priority**: `P0` (не собирается, падает, лаунчер не открывается) · `P1` (заметно портит пользование) ·
  `P2` (важно, но живётся) · `P3` (полировка, идеи)
- **area**:

  | area | Что это |
  |---|---|
  | `ui` | `XmbView`: раскладка, колонка, ряд разделов, меню, подсказки, карточка, док на экране |
  | `look` | оформления, фон и шейдеры (`BgRenderer`, `WaveShader`), шрифты, живые обои |
  | `icons` | значки приложений: силуэты, своей формы, пакеты, формы (`GlyphArt`, `AppGlyphs`, `IconShapes`) |
  | `search` | поиск (`SearchLayer`, `AppSearch`) |
  | `apps` | список приложений, разделы (`Categories`), «Частые», док, ярлыки (`AppRepository`) |
  | `input` | жесты, отклик, геймпад и клавиши, кнопка Essential, поворот |
  | `media` | фото, музыка, видео как на PSP |
  | `system` | уведомления, календарь, строка состояния, лаунчер по умолчанию, жизненный цикл |
  | `store` | сборки full/store, подпись, Google Play, документы `docs/play/` |
  | `docs` | README, CLAUDE.md, скиллы |
  | `infra` | сборка, SDK, эмулятор, трекер, git |

- **source**: `agent` | `user` | `review-YYYY-MM-DD`
- **verify-in**: где подтверждается — `review` (автор на своём телефоне) | `device` (приставка, планшет, другой
  телефон) | `emulator` (агент на своём AVD) | `build` | `none`; обязательно для `bug` и `feature`
- **labels**: свободные метки; `watch` = «разово наблюдалось, следить»

## Статусы

```
bug/feature/tech/question:
  open → in-progress → fixed → verified
                         └─(ревью не подтвердило)→ open
  из любого: wontfix, cannot-reproduce, closed
decision:  accepted → superseded
```

`fixed` — поправлено, **не проверено**; `verified` — проверка подтвердила, его агент сам не ставит. Терминальные
статусы переоткрываются только через `-Force`.

## Петля ревью

1. Агент делает шаг → ставит сборку на телефон → `set -Status fixed -Commits <hash>`; в заметке — что именно
   попробовать: какое оформление, ориентация, какие кнопки.
2. Перед ревью → `checklist`.
3. Автор отмечает вердикты в board.html и сохраняет фидбек → агент выполняет `apply`.
4. Подтвердилось → `verified`; нет → `open` с записью, что осталось.

## Когда агент ОБЯЗАН завести тикет

- Пришёл фидбек — по тикету на пункт.
- Автор принял решение в диалоге → `decision` **в ту же сессию**.
- Нашёл баг, который сейчас не чинит, или работу отложили — тикет вместо TODO в чате.

## Когда агент ОБЯЗАН обновить тикет

- Начал → `in-progress`; сделал → `fixed` + `-Commits`, и `LNC-…` в теле коммита.
- Конец сессии, если тикеты трогались → `board` + `validate`, закоммитить вместе с кодом.

## Чего агент НЕ делает

- Не ставит `verified` сам и не удаляет тикеты; не правит BOARD.md руками.
- Не плодит дубли: перед `new` — поиск по `tickets/` на похожий заголовок.
